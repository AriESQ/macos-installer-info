# DaVinci Resolve 21.0.0b — macOS installer findings

- **Package:** `Install Resolve 21.0.0b.pkg` (from `/Volumes/Blackmagic DaVinci Resolve/`)
- **Analyzed:** 2026-05-23
- **Source:** notarized installer, signed by Blackmagic Design Inc (Team ID `9ZGFBWLSYP`), timestamped 2026-05-12.
- **Working tree:** `/tmp/pkg_analysis_1779562331/` (Lite payload extracted to `…/ManifestLite.pkg/extracted/`, 4.8 GB)

## TL;DR

DaVinci Resolve 21.0.0b ships as a **universal (x86_64 + arm64) binary**, but its `Distribution` XML omits `hostArchitectures`. That mismatch causes macOS Installer to prompt for Rosetta 2 on Apple Silicon even though the main executable runs natively. The prompt is **spurious at install time**, but Rosetta is still genuinely needed at runtime for several Intel-only codec/panel dylibs bundled inside the app.

## False Rosetta prompt — root cause and fix

The installer-time Rosetta prompt on Apple Silicon is caused by missing metadata, not by any actual Intel-only code in the main launch path. Installer.app uses the Distribution-level `hostArchitectures` attribute to decide whether Rosetta is required; absent that attribute, it assumes Intel-only and prompts.

**Fix (would have to be applied upstream by Blackmagic):** add to `Distribution`

```xml
<options customize="allow" allow-external-scripts="no" rootVolumeOnly="true"
         hostArchitectures="x86_64,arm64"/>
```

## Runtime Rosetta is still required for some features

Inside the Resolve.app bundle there are **exactly 22 x86_64-only Mach-O binaries** (verified by walking every executable / `.dylib` under the extracted Lite payload and filtering with `lipo -archs`). These will fault into Rosetta when the relevant features are exercised, even on an otherwise-native arm64 launch.

Helper executables (`Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Applications/`):

- `EuphonixPanelDaemon` — Euphonix control surface daemon
- `JLCooperPanelDaemon` — JLCooper control surface daemon
- `TangentPanelDaemon` — Tangent control surface daemon
- `pg_dump` — bundled Postgres dump tool
- `pg_restore` — bundled Postgres restore tool

Codec dylibs (`…/DaVinci Resolve.app/Contents/Libraries/`):

- `csehqa.dylib` — Cineform HQA
- `cseuvec.dylib` — Cineform UVec

- `libsavcehpp.dylib` — Sony AVC HPP

- `libsonyxavcenc.dylib` — Sony XAVC encoder

The same eight dylibs are mirrored under the XPC service (`…/DaVinci Resolve.app/Contents/XPCServices/IOXPC.xpc/Contents/Libraries/`):

Total: 5 helpers + 8 dylibs + 8 mirrored dylibs + 1 XPC binary = **22**. No Intel-only binaries were found outside `DaVinci Resolve.app` (the seven other shipped apps and their frameworks are all universal).

Implication: ticking the "false Rosetta prompt" off the Distribution XML would silence the install dialog, but a user editing XAVC media, using a Tangent/Euphonix/JLCooper panel, or invoking Postgres maintenance would still spawn Rosetta processes at runtime. Removing Rosetta entirely is not viable for this build.

## Process notes — why `analyze_pkg.sh` produced a misleading report

The script's first run reported "Intel-Only Package" despite the package being universal. Three bugs in `analyze_pkg.sh` combined:

1. **Hardcoded `gunzip` on Payloads** (`analyze_pkg.sh:86`). This pkg's Payloads are raw cpio (`070707`), so `gunzip -dc` printed `unknown compression format` and emitted no bytes. Need format detection (gzip / xz / pbzx / raw cpio) via `file -b` or magic-byte sniffing.
2. **Silenced cpio errors** (`cpio -id 2>/dev/null`). With nothing on stdin, cpio failed silently, so no app tree existed when the per-app loop ran.
3. **Summary heuristic trusts extraction success.** `HAS_ARM64_BINARY` is set from `find … -exec file …`, which returns nothing when the payload was never extracted. The summary then falls back to "Intel-Only" instead of saying "extraction failed; verdict unreliable."

A quick replacement for step (1):

```sh
case "$(file -b Payload)" in
  *gzip*) gunzip -dc Payload | cpio -id ;;
  *XZ*)   xz -dc Payload     | cpio -id ;;
  *cpio*) cpio -id < Payload ;;
  *)      echo "Unknown Payload format: $(file -b Payload)"; return 1 ;;
esac
```

…and drop the `2>/dev/null` on the cpio call so failures surface.

## Command-line approaches used to interrogate this installer

Every command below uses stock macOS tools — no Homebrew or third-party dependencies. The sequence is roughly the order it was executed in during this investigation; substitute your own paths.

```sh
PKG='/Volumes/Blackmagic DaVinci Resolve/Install Resolve 21.0.0b.pkg'
WORK=/tmp/pkg_analysis
mkdir -p "$WORK"
```

### 1. Identify the package and verify the signature

```sh
# What kind of file is it? Expect "xar archive" for flat pkgs.
file "$PKG"

# Verify Developer ID / notarization / certificate chain.
pkgutil --check-signature "$PKG"
```

### 2. Expand the outer package

`--expand` unpacks the xar wrapper but does NOT unpack the inner `Payload` cpio streams.

```sh
pkgutil --expand "$PKG" "$WORK/expanded"
ls -la "$WORK/expanded"          # Distribution, Resources/, *.pkg/ component dirs
```

### 3. Read the Distribution XML

This is where `hostArchitectures`, OS version checks, and the choice tree live.

```sh
cat "$WORK/expanded/Distribution"

# The single most important question for false-Rosetta diagnosis:
grep -i hostArchitectures "$WORK/expanded/Distribution" || \
  echo "hostArchitectures NOT declared — Apple Silicon will prompt for Rosetta"
```

### 4. Inspect each component sub-package

```sh
for p in "$WORK/expanded"/*.pkg; do
  echo "=== $(basename "$p") ==="
  cat "$p/PackageInfo"          # identifier, version, scripts, payload size
  ls -la "$p"                   # Bom, PackageInfo, Payload, Scripts/
  ls "$p/Scripts" 2>/dev/null   # preinstall / postinstall hooks
done
```

### 5. Identify the Payload compression format

The script's `gunzip` step assumes gzip; modern pkgs vary. Sniff the first bytes.

```sh
for p in "$WORK/expanded"/*.pkg/Payload; do
  echo "=== $p ==="
  file "$p"
  head -c 16 "$p" | xxd
done
```

Magic-byte cheat sheet:

| First bytes | Format | Extract with |
|---|---|---|
| `1f 8b` | gzip | `gunzip -dc Payload \| cpio -id` |
| `fd 37 7a 58 5a` | xz | `xz -dc Payload \| cpio -id` |
| `pbzx` (ASCII) | Apple pbzx | needs an unpacker (no stock tool) |
| `30 37 30 37 30` (`07070…`) | raw cpio | `cpio -id < Payload` |
| `78 61 72 21` (`xar!`) | nested xar | `xar -xf Payload` |

### 6. List a Payload's table of contents without extracting

Useful for the 5 GB Lite Payload — `cpio -it` reads headers only.

```sh
cpio -it < "$WORK/expanded/ManifestLite.pkg/Payload" 2>/dev/null \
  | grep -E '\.app/Contents/MacOS/[^/]+$' | head -20
```

### 7. Selective extraction (single files, not the whole 5 GB)

cpio takes optional path patterns after the flags.

```sh
mkdir -p "$WORK/cherrypick"; cd "$WORK/cherrypick"
cpio -id --quiet \
  './Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/MacOS/Resolve' \
  './Applications/DaVinci Resolve/DaVinci Resolve.app/Contents/Info.plist' \
  < "$WORK/expanded/ManifestLite.pkg/Payload"
```

### 8. Full extraction

```sh
cd "$WORK/expanded/ManifestLite.pkg" && mkdir -p extracted && cd extracted
cpio -id --quiet < ../Payload
du -sh .
```

### 9. Per-app inspection

For each `.app`, resolve the main executable through `Info.plist`, then probe it.

```sh
APP="$WORK/.../DaVinci Resolve.app"
PLIST="$APP/Contents/Info.plist"
EXEC=$(defaults read "$PLIST" CFBundleExecutable)
MAIN="$APP/Contents/MacOS/$EXEC"

file "$MAIN"                 # Mach-O universal / x86_64 / arm64?
lipo -archs "$MAIN"          # one-line architecture list
lipo -info  "$MAIN"          # same, prefixed with file name
lipo -detailed_info "$MAIN"  # offsets, sizes, alignment — useful for thin-ing
```

Bundle metadata via `defaults` (note `defaults` wants a path with no `.plist` extension when using full paths — and chokes on missing keys, so swallow stderr):

```sh
defaults read "$PLIST" CFBundleIdentifier          2>/dev/null
defaults read "$PLIST" CFBundleShortVersionString  2>/dev/null
defaults read "$PLIST" LSMinimumSystemVersion      2>/dev/null
defaults read "$PLIST" LSRequiresNativeExecution   2>/dev/null
defaults read "$PLIST" LSArchitecturePriority      2>/dev/null
```

For a structured, complete dump, prefer `plutil`:

```sh
plutil -p "$PLIST"                                  # pretty-print
plutil -convert xml1 -o - "$PLIST"                  # XML to stdout
plutil -extract NSCameraUsageDescription raw "$PLIST"
plutil -convert xml1 -o - "$PLIST" | grep -A1 'UsageDescription</key>'
```

### 10. Codesign, hardened runtime, entitlements

```sh
codesign -dv "$MAIN"                            # one-line summary
codesign -d -vv "$MAIN"                         # authority chain, TeamID, flags
codesign -d -vv --entitlements - "$MAIN"        # XML entitlements to stdout
codesign -d --entitlements :- "$MAIN" \
  | plutil -convert xml1 -o - -                 # entitlements as clean XML
codesign --verify --deep --strict --verbose=2 "$APP"   # tamper / seal check
spctl --assess --type install -vv "$PKG"        # Gatekeeper verdict on the .pkg
spctl --assess --type execute -vv "$APP"        # Gatekeeper verdict on the .app
```

### 11. Architecture sweep across the whole bundle

Find every Mach-O under the extracted tree and classify it.

```sh
EX="$WORK/expanded/ManifestLite.pkg/extracted"

# All Mach-O files, with their architectures:
find "$EX" -type f \( -name '*.dylib' -o -perm +111 \) 2>/dev/null | while read f; do
  file "$f" 2>/dev/null | grep -q Mach-O || continue
  printf '%-12s %s\n' "$(lipo -archs "$f" 2>/dev/null)" "$f"
done

# Intel-only binaries (the ones that will trigger Rosetta at runtime):
find "$EX" -type f \( -name '*.dylib' -o -perm +111 \) 2>/dev/null | while read f; do
  file "$f" 2>/dev/null | grep -q Mach-O || continue
  A=$(lipo -archs "$f" 2>/dev/null)
  echo "$A" | grep -q x86_64 && ! echo "$A" | grep -q arm64 && echo "$f"
done

# arm64-only binaries:
find "$EX" -type f \( -name '*.dylib' -o -perm +111 \) 2>/dev/null | while read f; do
  file "$f" 2>/dev/null | grep -q Mach-O || continue
  A=$(lipo -archs "$f" 2>/dev/null)
  echo "$A" | grep -q arm64 && ! echo "$A" | grep -q x86_64 && echo "$f"
done
```

### 12. Linkage and load commands

If you want to know *what* a binary pulls in (codecs, frameworks, system libs):

```sh
otool -L "$MAIN"             # linked dylib paths + versions
otool -l "$MAIN" | less      # all load commands (LC_VERSION_MIN_*, LC_BUILD_VERSION, rpaths…)
otool -hv "$MAIN"            # Mach-O header flags (PIE, TWOLEVEL, etc.)
nm -gU "$MAIN" | head        # exported symbols
```

